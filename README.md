# 挣值项目看板

零依赖的挣值管理（EVM）看板：把工作包预算、计划进度、实际完成与成本放在同一张报表里，
选择截止日期后查看 PV / EV / AC、偏差、基线与完工预测。界面为原生 ES 模块 + SVG，
无需构建步骤。

## 运行

```bash
npm test        # 核心引擎单元测试（node --test）
npm run serve   # 静态服务，打开 http://127.0.0.1:4173/
```

也可以直接打开 `index.html`（部分浏览器对 `file://` 下的 ES 模块有限制，推荐用
`npm run serve`）。

## 数据口径

### 计量方式（决定 EV）

- `milestone`：按里程碑权重；有 `completedDate` 的按日期计入，没有日期的完成状态
  只能从观测日起生效。
- `quantity`：`completedQuantity / plannedQuantity`；历史取值来自 `history`。
- `weighted`：各步骤 `percent × weight`，同样支持 `history`。
- 没有计量方式、计划数量为零、里程碑权重为零都返回 `ratio: null`（不是 0），
  报表显示“无法计量”，不输出 CPI/SPI。

挣值永远由“预算 × 计量完成比例”得到，不会用已花成本替代进度。

### 父子工作包

有子节点的工作包只做汇总，自身不计量、不产生 EV/AC；项目总额只累加叶子节点，
因此父级与子级不会重复计入。

### 双日期成本

每条成本记录同时保存：

- `effectiveDate`：实际发生日期（决定它落在曲线的哪一天）；
- `recordedDate`：登记日期（决定截止日期当天“当时已知”是否看得到它）。

`asOf` 之后发生的成本不计入 AC；在 `asOf` 之前发生、但在 `asOf` 之后才登记的记录，
在“当时已知”口径下隐藏并在成本补录面板中列出，切到“当前更正”后才计入。
提前采购的预付款按发生日期入账，不会被当作未来成本。

### 截止日期、数据截止与观测

- `asOf` 是报表截止日期，决定 PV 与成本口径。
- `project.dataThrough`（样本用 `asOfDefault`）是进展实际观测到的日期，默认与
  `asOf` 相同。把报表重开到更早的日期时，只使用当时的日期化记录（历史、里程碑
  完成日期）；晚于该日期的“当前测量值”不会被倒填进旧报表。
- 当 `asOf` 晚于数据截止日期时，EV 停在最后一个观测日，AC 仍可继续累计（例如
  截止后才登记的补录），图表会在说明中分别标出两条线的观测终点。

### 基线

`baselines` 为数组，每项含 `items`（`packageId, bac, start, finish, milestones`）。
调整范围或预算时用 `saveBaseline` 追加新版本并设为当前，旧版本的预算与日期保持原样，
可随时切回查看；历史偏差不会因为改基线而消失。不在所选基线内的新工作包标为
“不在基线范围”，不参与该基线的 PV/EV/AC 汇总。

### 预测

- 基准 EAC = `BAC / CPI`，仅在 EV 与 AC 都大于零时给出，否则说明原因；
- 用户情景 EAC = `AC + 用户填写的剩余成本`，与基准情景互相独立；
- 假设随结果一并展示；当进展观测早于报表截止日期时会额外注明。

### 图表

单一金额轴（万元），累计 PV / EV / AC 三条线，2px 线宽、带描边端点、选定值直接标注，
十字准线 + 提示框，支持方向键浏览，并提供与图表等价的表格视图。
